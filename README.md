# 绝区零·助手

Windows / macOS 桌面客户端，共用功能与存档格式。默认最大化（非全屏），保留系统标题栏，左侧导航可折叠。

## 安装

当前版本 3.2.2，构建输出位于 `dist/`：

| 系统 | 文件 | 使用方式 |
| --- | --- | --- |
| Windows x64 | `ZZZ-Helper-3.2.2-win-x64.exe` | 双击运行，免安装 |
| macOS Apple Silicon（M 系列） | `ZZZ-Helper-3.2.2-mac-arm64.dmg` | 打开后将“绝区零·助手”拖入 Applications |
| macOS Intel | `ZZZ-Helper-3.2.2-mac-x64.dmg` | 打开后将“绝区零·助手”拖入 Applications |

macOS 默认提供 DMG，需要 ZIP 时运行 `npm run build:mac:zip` 单独生成。当前 macOS 包采用本地 ad-hoc 签名，没有 Apple Developer ID 签名和公证。macOS 若阻止首次启动，请通过系统设置的“隐私与安全性”查看并确认此应用；不需要关闭系统安全保护。正式对外发布的签名配置见 [双平台开发与发布](docs/CROSS-PLATFORM.md)。

macOS 支持 ⌘C / ⌘V / ⌘A 等编辑快捷键。关闭窗口后应用保留在 Dock，点击 Dock 图标重新打开；⌘Q 完全退出。

## 使用

1. **角色列表**：60 位正式服角色，使用真正头像的横向卡片。按属性、职业、阵营或稀有度分组，可折叠分组并筛选持有状态及配置；不设页面搜索框。详情提供每名角色的输出机制、循环、操作限制、养成重点和至少两套配队，可展开查看原文与来源；同时展示全部账号属性及基础/追加值、技能、六段影画、觉醒、音擎和六槽驱动盘。
2. **现有配置**：账号数据只读；缺失数据显示提示，不以演示值补齐。
3. **预设配置**：每个角色支持多个独立方案，默认提供九档：00、01、11、21、31、41、51、61、65。00 为 0 影画与适配的 1 星泛用 S/A 音擎，其余两位分别表示影画与专武星级。新预设默认 21；仅正式服已开放角色默认潜能影像 P6。各档分别按角色机制、音擎及推荐套装与合法主词条生成六张 S 级盘，配置 40 次优先副词条并保留 14 次填充。可新建、复制、重命名、删除自定义方案；九档可以编辑但不能删除；旧标配保留为独立方案。未开放潜能影像的角色标注为不可设置。支持自由词条、养成和精确值编辑、现有/预设对比。
4. **队伍比较**：固定同一目标及配置方案，分别选择 A、B 队的两名队友和各自方案。同一队友可以在两队使用不同预设；编辑器切换方案不会改变队伍引用。两列对照表逐行展示整体提升、增益指标及部件来源；差异项在前，用 A 蓝色、B 橙色区分，相同数值靠后，缺失来源明确标注。同／异增益分组可折叠，明细支持按角色折叠，并显示头像与来源角色。只统计两名队友给目标的增益及部件来源。目标自身入场面板作为基准，自身技能、影画、音擎和四件套战斗效果不进入整体提升。
5. **现有抽取建议**：队伍比较下方的新菜单。按持有角色推荐不重复的 1–3 队与养成顺序，再列补位、成型队专武与影画规划。可设置抽数预算、垫抽与大保底。队伍及预设显示限定金与全部 S 金；抽取选项显示新增金、最坏出 S 次数、抽数与菲林。依据资源循环、抢场与技能条件排序，不声称实测 DPS 最优。
6. **同步数据**：使用已保存的米游社登录读取国服绑定账号，再同步全部角色。扫码和官方网页登录均可使用。只更新现有配置，保留预设。
7. **计算公式**：列出公式、固定敌人参数、来源和边界。

整体提升是同一招式在满层增益生效窗口中的收益，不代表整队 DPS。未映射的技能、觉醒或特殊结算会提示具体原因并暂停整体百分比，避免把缺失效果当作零。

所有下拉可搜索，角色、音擎、套装选项带图标；名称、属性、职业及持有状态按列对齐。复制现有装备时保留精确词条值，取消对应“自定义”后可恢复按等级计算。

## 存档

自动保存位置：

- Windows：`%APPDATA%/ZZZ Buff Studio/records.json`
- macOS：`~/Library/Application Support/ZZZ Buff Studio/records.json`

自动保存并保留上次 `.bak`；已移除导入与手动备份功能。当前使用 v7 存档，兼容 v1–v6。v6 升级新增六个档位，保留已修改的三档、全部自定义方案与队伍引用；仅精确匹配旧出厂配置的 00 自动补入新音擎。最多 36 个方案可容纳原有 30 个及新增六档。抽取设置随存档保存。原 v5 的全部方案、装备与队伍引用继续保留。旧“标配”显示为“原标配”，已有队伍继续使用原引用，编辑器默认标准方案转到 21；自定义编辑方案保留。2.1 及更早预设保留为“原预设”，未经修改的原始配置另存于 `originalBuild`，包括曾设置到未开放角色的潜能数值；此类数值不参与计算。旧手动增益保留在 `legacy` 归档。

Windows 与 macOS 共用存档格式。登录状态保存在各自的独立会话中，在新电脑上需要重新扫码登录。

登录与设备信息只存在本客户端官方登录分区，不写入角色 JSON 或备份，不扫描系统浏览器或游戏进程。

## 开发

```sh
npm ci
npm start
npm test
npm run smoke
npm run test:ui
npm run test:desktop
npm run build
```

`npm run build` 构建当前系统，Windows 生成 x64 EXE，macOS 生成当前架构 DMG。发布使用 `npm run build:win` 和 `npm run build:mac`（同时构建 arm64、x64）。必须在 macOS 上构建 macOS 包；Windows 包建议在 Windows 上构建。

测试和打包验证完成后执行 `npm run clean`：保留当前版本 Windows EXE 和两种 macOS DMG，清除历史安装包、重复 ZIP、未压缩构建目录及已知测试缓存。`npm run clean -- --dry-run` 只预览。开发依赖、资料生成输入和正式存档保留；清理后若要运行 `test:package`，需重新打包生成未压缩应用。CI 会在产物测试后清理，减少保留的重复文件。

后续更新必须同时支持 Windows 和 macOS，详见 [AGENTS.md](AGENTS.md)。GitHub Actions 已配置 Windows x64、macOS arm64 与 Intel x64 的测试和打包；将项目纳入 GitHub 仓库后即可启用。

版本号与游戏正式版本联动：当前游戏 3.2 对应助手 3.2.1、3.2.2 等；游戏升级后从新游戏版本的补丁号 1 开始。每次更新使用 `npm run version:next`，所有打包命令都会先运行 `npm run version:check`，校验游戏版本、助手版本、lockfile 和侧栏一致。更新完成只保留当前版本安装包，删除旧版本并重新安装、重启本机应用。

本次更新新增 60 名角色机制与配队、九档预设和现有抽取建议，详见 [推荐与金数口径](docs/RECOMMENDATIONS.md)。验证后重新安装、重启本机 macOS 应用，并清理旧版本及构建与测试产物。

冒烟与多方案测试使用隔离目录和模拟账号。`npm run dev` 提供浏览器预览。来源和边界见 [标配方案](docs/STANDARD-BUILDS.md)、[数据来源](docs/DATA-SOURCES.md)、[计算公式](docs/formulas.md)、[账号同步](docs/account.md)。
